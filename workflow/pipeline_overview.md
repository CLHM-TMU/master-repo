# 16S rRNA Amplicon Sequencing Pipeline — Overview

This Snakemake pipeline processes 16S rRNA amplicon sequencing data (NGS or TGS) from raw reads through to diversity analyses, differential abundance testing, and functional prediction. Each stage is described below.

---

## Stage 0 — Setup & Validation

**Rule:** `make_dirs`

Before any analysis begins, the pipeline:

- Validates the configuration (sequence type, targeted region, analysis mode, reference databases, experimental design).
- Creates all required output directories (`raw_data/`, `qiime2_artifacts/`, `plots/`, `tables/`, `tmp/`, and subdirectories for diversity, taxa barplots, and differential abundance).
- Reads the sample metadata (`metadata.tsv`) and determines which grouping axes (experimental factors) will drive downstream comparisons.

Two **analysis modes** are supported:
- **`lite`** — uses a single composite grouping label; runs LEfSe only.
- **`standard`** — uses one or more defined factors, optional covariates, and optional interaction terms; runs ANCOMBC2 and LEfSe.

---

## Stage 1 — Manifest Building

**Rule:** `generate_manifest` → `scripts/build_manifest.py`

Scans the `raw_data/` directory and builds a QIIME2-compatible manifest TSV file that maps sample IDs to their raw FASTQ file paths. The manifest format differs slightly between NGS (paired-end) and TGS (single-end CCS) input.

---

## Stage 2 — Adapter Trimming & Denoising

**Rules:** `NGS.smk` or `TGS.smk` (selected based on `SEQUENCE_TYPE`)

### 2a. Import
Raw reads are imported into QIIME2 as a demultiplexed artifact (`demux.qza`).
- **NGS**: imported as paired-end sequences (`PairedEndSequencesWithQuality`).
- **TGS**: imported as single-end sequences (`SequencesWithQuality`).

### 2b. Primer Trimming (Cutadapt)
Adapter/primer sequences are removed using `qiime cutadapt`.
- **NGS**: trims the standard V3V4 primer pair (341F/806R with Nextera adapter overhangs), allowing up to 10% error rate.
- **TGS**: currently passes sequences through without trimming (the cutadapt step is a placeholder; primer trimming is handled later in DADA2 via `--p-front`).

### 2c. Quality Profiling & Truncation Length Selection (NGS only)
- Quality scores are exported from the trimmed demux visualisation.
- `generate_trunc_length.py` automatically determines forward and reverse truncation lengths by finding where median quality drops below Q20.

### 2d. DADA2 Denoising
Sequences are denoised to produce **Amplicon Sequence Variants (ASVs)**:
- **NGS** (`denoise-paired`): paired-end reads are quality-filtered, denoised, merged, and chimera-filtered. Truncation lengths are applied automatically from Stage 2c.
- **TGS** (`denoise-ccs`): PacBio CCS reads are processed using the full-length denoising workflow with a 5′ primer anchor; no truncation is applied.

Outputs:
- `table-dada2.qza` — ASV feature table (samples × ASVs).
- `rep-seqs-dada2.qza` — representative sequences for each ASV.
- `dada2-stats.qza/.qzv` — per-sample denoising statistics.

### 2e. Optional Sample Filtering
If `IGNORE_SAMPLES` is specified in the config, pre-filter outputs are preserved as `unfiltered-*`, and a filtered table/rep-seqs pair is generated by removing the unwanted samples from both the feature table and the representative sequences.

### 2f. Rarefaction Depth Determination
The feature table is exported and the **minimum per-sample read count** is automatically selected as the rarefaction depth for diversity analyses (`rarefy_depth.csv`).

---

## Stage 3 — Taxonomy Classification & Phylogeny

**Rules:** `Greengenes2.smk` and/or `Silva138.smk` (one or both, based on `REFERENCE_DB`)

### 3a. Taxonomic Classification
Representative sequences are classified against a pre-trained Naive Bayes classifier for the chosen reference database and amplicon region:

| Database | V3V4 classifier | Full-length classifier |
|---|---|---|
| Greengenes2 | `2024.09.custom.V3V4.nb.qza` | `2024.09.backbone.full-length.nb.qza` |
| SILVA 138 | `2024.09.custom.V3V4.nb.qza` | `2024.09.backbone.full-length.nb.qza` |

This produces a taxonomy artifact (`.qza`) and a tabular visualisation (`.qzv`).

### 3b. Phylogeny Construction
A phylogenetic tree is built by inserting ASVs into the full-length backbone sequence database using `qiime greengenes2 non-v4-16s` (or its SILVA equivalent). This produces a phylogeny-aware feature table and representative sequences, which are required for UniFrac diversity metrics.

### 3c. Taxa Barplot Visualisations
- **QIIME interactive barplot** (`.qzv`) — generated natively in QIIME2.
- **Custom static barplots** (`.png`) — generated per taxonomic level (Kingdom → Species) and per grouping axis using `make_taxa_barplot.py`, showing the top 20 taxa per group.

### 3d. Artifact Export
The feature table (`.biom`), representative sequences (`.fna`), and taxonomy assignments (`.tsv`) are exported from QIIME2 for use in downstream non-QIIME tools (differential abundance, PICRUSt2).

---

## Stage 4 — Diversity Analyses

**Rules:** `rarefy_table`, `diversity.smk`

### 4a. Rarefaction
The ASV feature table is rarefied to the depth determined in Stage 2f to normalise sequencing effort across samples.

### 4b. Alpha Diversity
Four within-sample diversity metrics are calculated for each reference database:

| Metric | What it measures |
|---|---|
| Shannon index | Species richness and evenness |
| Chao1 | Richness estimator (accounts for rare species) |
| Simpson index | Dominance / evenness |
| Pielou's evenness | How evenly abundances are distributed |

Results are plotted as grouped box/violin plots per grouping axis (`plot_alpha_diversity.py`).

### 4c. Beta Diversity
Four between-sample dissimilarity matrices are computed:

| Metric | Phylogenetic? | What it captures |
|---|---|---|
| Jaccard | No | Presence/absence overlap |
| Bray-Curtis | No | Abundance-weighted overlap |
| Unweighted UniFrac | Yes | Presence/absence + phylogenetic distance |
| Weighted UniFrac | Yes | Abundance-weighted phylogenetic distance |

PCoA ordinations are computed for all four matrices and plotted as 2D scatter plots coloured by grouping axis (`plot_beta_diversity.py`).

### 4d. Statistical Testing (PERMANOVA / BetaDisper)
For all four distance matrices and all grouping axes, the pipeline runs:
- **PERMANOVA** — tests whether group centroids differ significantly.
- **BetaDisper** — tests whether group dispersions (spread) are homogeneous (a prerequisite for interpreting PERMANOVA).

Results are saved to `permanova_betadisper.tsv`.

---

## Stage 5 — Differential Abundance Analysis

**Rules:** `LEfSe.smk`, `ANCOMBC2.smk`

The methods run depend on analysis mode:

### LEfSe (Linear Discriminant Analysis Effect Size)
Available in both `lite` and `standard` modes. Uses the exported `.biom` feature table and taxonomy TSV as input.

For each grouping axis:
- **`run_lefse.R`** — runs LEfSe to identify taxa that are significantly enriched in one or more groups, ranked by LDA score.
- **`plot_lefse.R`** — generates:
  - **LDA bar chart** (`.svg`) — ranked differentially abundant taxa with LDA scores.
  - **`LEfSe_Cladogram_by_{group}.svg`** — attempts `plot_cladogram()` from `microbiomeMarker`; if that call fails (e.g. due to missing tree data), the script falls back silently and writes a duplicate of the LDA bar chart to this file instead. In practice this output is not currently a true cladogram.

### ANCOMBC2 (Analysis of Compositions of Microbiomes with Bias Correction 2)
Available in `standard` mode only. A model-based approach that corrects for sampling fraction bias and supports multi-factor designs with covariates and interaction terms.

For each factor:
- **`run_ancombc2.R`** — fits the ANCOMBC2 model and outputs a results table (`.tsv`).
- **`plot_ancombc2_results.R`** — generates:
  - **Volcano plot** (`.png`) — log-fold change vs. significance.
  - **Heatmap** (`.png`) — significant taxa across samples, with a legend mapping short IDs to full taxonomy (`.tsv`).

---

## Stage 6 — Functional Prediction with PICRUSt2 (optional)

**Rules:** `PICRUSt2.smk` (only if `RUN_PICRUST2: true`)

PICRUSt2 predicts the functional potential of the microbial community from 16S marker gene data alone, without requiring shotgun metagenomics.

### 6a. PICRUSt2 Pipeline
Using the exported `.fna` representative sequences and `.biom` feature table, the full PICRUSt2 pipeline is run to predict:
- **KEGG Orthology (KO)** metagenome abundances.
- **Enzyme Commission (EC)** number abundances.
- **MetaCyc pathway** abundances.

### 6b. Add Descriptions
`add_descriptions.py` annotates each KO, EC, and pathway ID with a human-readable description.

### 6c. Visualisation
`plot_picrust_heatmap.R` generates a summary heatmap (`.pdf`) of predicted pathway abundances grouped by sample metadata.

|---|---|
| 0 — Setup | Directory structure, validated config |
| 1 — Manifest | `manifest.tsv` |

| 3 — Taxonomy | `{db}-taxonomy.qza`, `{db}-taxa-bar-plots.qzv`, `taxa_barplot_*.png` |
| 4 — Diversity | Alpha/beta plots, `permanova_betadisper.tsv` |
| 5 — Diff. Abundance | LEfSe LDA SVG + cladogram SVG (fallback to LDA if cladogram fails), ANCOMBC2 volcano + heatmap PNGs |
| 6 — Function | PICRUSt2 KO/EC/pathway TSVs, `picrust2_heatmap.pdf` |
